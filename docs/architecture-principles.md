# Yggdrasill 架构总原则（Architecture Principles）

> 状态：v1 终态（2026-10-29 终态整理）
> 上游文档：`docs/vision.md`

## 1. 分层架构

```text
┌─────────────────────────────────────────────┐
│ 表现层（可替换：Web / 微信小游戏 / Godot）      │ ← 只做渲染、输入、音频
├─────────────────────────────────────────────┤
│ 规则内核（纯逻辑，无 IO，确定性可回放）          │ ← 实体/属性/状态机/事件/条件
├─────────────────────────────────────────────┤
│ Mod 运行时（确定性 Lua 沙箱 + 资源数据加载校验）  │ ← Lua 唯一可执行接口 + Schema 资源契约（D11/D15）
├─────────────────────────────────────────────┤
│ 内容管线（AI 生成 → Schema 校验 → 发布）       │ ← M1 阶段接入
└─────────────────────────────────────────────┘
```

## 2. 三条铁律

1. **内核零渲染依赖**——规则内核是纯函数式的状态转换机 `(state, event) → state'`。
   - 这是 M4 多人模式（指令回放/状态同步）的入场券
   - 内核不 import 任何 DOM / 平台 API / 渲染库
   - 状态可携带 `pending_choice`（choice-as-state：挂起即数据，玩家选择作为新外部事件，铁律一字不改）；每转换的叙事输出缓冲为瞬态面，不入档（D-B2/D-B3，2026-10-27 设计定稿）
2. **Lua 唯一可执行接口 + 资源化数据**（D11）——Mod 的一切可执行逻辑（叙事、效果、条件）均以 Lua 编写，运行于确定性沙箱（D16：Lua 5.4）；大体积静态内容为资源文件，受控 API（`ygg.data(...)`）加载并过 JSON Schema 校验（D15）。
   - 副产品更新：脚本沙箱安全面由沙箱硬约束集承载（D13：无 IO/时钟、燃料/内存上限、API 白名单、确定性执行），内容审核面收敛为「资源数据校验 + 脚本静态检查」
3. **图文冒险 = RPG 的子集**——内核组件不绑定叙事语义，领域系统（叙事/任务/战斗）是内核机制的「领域应用」。

## 3. 规则内核组件（M0 范围）

```text
自研规则内核
├── 3.1 实体表
├── 3.2 事件系统
├── 3.3 状态机服务      ← 语义承载移至 ygg Lua stdlib（D11）
├── 3.4 条件表达式      ← 已移除（D11）——条件表达式归 Lua
└── 3.5 叙事流          ← stdlib 语义面（D11）
```

### 3.1 实体表（角色与道具管理）

- 实体 + 属性（数值/文本/引用）+ 标签
- **M0 不引入 ECS**（bitECS 等面向实时帧循环与海量实体，图文冒险实体规模为几十~几百、事件驱动更新，普通实体表即可）
- 自研实现，但**借鉴 bitECS 的组件化建模 + 内置序列化思想**
- 序列化：状态快照 + 版本号（为 Mod 更新后的兼容策略打底）

### 3.2 事件系统

- 事件总线 + 触发器（trigger：事件匹配 + 条件）+ 效果（effect：改属性 / 发事件 / 状态转移）
- 事件驱动是内核的唯一驱动方式（不轮询）
- 事件流全程可记录 → 支撑回放与调试

### 3.3 状态机服务（显式通用 FSM）

**定位**：叙事流/任务/战斗共用的通用机制。**语义承载在 ygg Lua stdlib**（随引擎版本化，D11，2026-10-27）——Mod 作者（AI）声明/使用状态机实例而不重复实现语义；Rust 侧提供实体表、事件总线与转换驱动数据面，内核 Rust 代码不含状态机语义（原「内核不改代码」表述更新）。

**语义收敛**（刻意保持薄，stdlib 语义面）：

- 扁平状态 + 转移规则（条件 + 入/出效果）
- 事件驱动转移：`onEvent(event) → 评估当前状态所有出边条件 → 命中则执行效果 + 切换状态`
- 当前状态查询纳入全局 state（可序列化）

**不引入 XState 的理由**（否决保留）：statecharts 语义（嵌套状态、并行区域、actor 模型等）远超所需；语义面越贴近领域语义，AI 生成可靠性越高。所需的状态机语义由 ygg Lua stdlib 承载（原「约两三百行可实现」的 Rust 表述更新）。

**各阶段复用**：

| 领域应用 | 阶段 | 状态语义示例 |
| --- | --- | --- |
| 叙事流 | M0 | 剧情节点 = 状态，选项 = 转移边 |
| 任务系统 | M3 | 未接 → 进行中 → 可交付 → 完成 |
| 战斗回合 | M3 | 选择行动 → 结算 → 检查终结 → 下一轮 |

### 3.4 条件表达式

**已移除（D11，2026-10-27）——条件表达式归 Lua**：自研声明式条件谓词引擎从内核范围移除；逻辑面失去静态 Schema 校验，验证转靠 lint + 沙箱试跑 + 资源 Schema 校验。原文本见 git 历史（json-rules-engine 仅存为谓词设计参考）。

### 3.5 叙事流

- 剧情节点 + 选项 + 条件跳转，语义由 **ygg Lua stdlib** 承载（narrative / fsm 语义面，随引擎版本化，D11）
- **choice-as-state**（D-B2 定稿）：`choice` 以 `pending_choice` 写入内核状态并终结当前 handler；玩家选择作为新外部事件进入转换驱动——「剧情节点 = 状态、选项 = 转移边」模型不变
- **叙事语义归 ygg Lua stdlib（D11，原 D5 自研对话树 JSON 路线已推翻）：**AI 生成可靠性靠 Lua 模板 few-shot 示例库 + 资源 Schema 校验 + 失败重生成回路兜底（D11/D15）
- [ink](https://github.com/inkle/ink) 仍为**设计参考**：借鉴其变量/分流/胶合文本等叙事语义设计；不引入 inkjs（JS 运行时与 Lua 语义面割裂）

## 4. 开源组件评估结论（2026-10-26 核实）

| 库 | 用途定位 | 结论 |
| --- | --- | --- |
| [ink / inkjs](https://github.com/inkle/ink)（MIT，5k★，活跃） | 叙事 DSL → 编译为 JSON → JS 解释器 | 📖 仅作叙事语义设计参考（结论保留；理由更新：叙事流语义归 ygg Lua stdlib，D11/D16；inkjs 为 JS 运行时，与 Lua 语义面割裂） |
| [json-rules-engine](https://github.com/CacheControl/json-rules-engine)（ISC，3.1k★） | JSON 条件谓词引擎 | 📖 仅作谓词设计参考，不引入（结论保留；理由更新：条件表达式归 Lua，D11——声明式谓词引擎从内核范围移除） |
| [bitECS](https://github.com/NateTheGreatt/bitecs)（MPL-2.0，1.5k★） | TS ECS，5kb，内置序列化 | ❌ M0 不引入，借鉴思想；M3 再评估 |
| XState | 通用状态机/statecharts | ❌ 语义过重，参考设计不引入 |

> 核查说明：以上活跃度基于当日 GitHub 页面核实；社区动态（如 inkjs 落后 ink 主版本的程度）未经搜索核实。

## 5. 可演进性保障（跨阶段检查点）

| 演进方向 | 架构保障 |
| --- | --- |
| 图文冒险 → RPG | 内核组件不绑定领域语义；M3 验收 = 复用内核不重写 |
| 单人 → 多人 | 纯函数式内核 `(state, event) → state'`；事件流可记录可回放 |
| Web → 微信小游戏/Godot | 表现层隔离；内核不触平台 API |
| Mod 资源格式契约演进 | 资源 Schema 带版本号；存档带双版本号（格式 + 引擎，D-B3）+ 迁移策略 |
| AI 生成可靠性 | Lua 模板 + 资源格式双目标设计、小而正交；配 few-shot 示例库与校验重生成回路（D11/D15） |
