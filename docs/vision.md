# Yggdrasill 项目愿景（Vision）

> 状态：v1 终态（2026-10-29 终态整理）
> 决策状态：✅ 已确认 / 📌 预留或已排期

## 1. 定位

**一个「游戏 + 平台」：数据驱动的规则内核作为游戏本体，AI 生成 Mod 作为无限内容供给（Lua 模板 + 数据填充，D11/D15）。**

对标 Minecraft 的双属性结构：

- 游戏本体价值：可玩、完整的核心体验
- 平台价值：规则引擎 + UGC 生态，内容供给无限化

**与 Minecraft 的关键差异**：AI 替代人类 Modder 的生产力。传统平台受限于 Mod 社区的创作瓶颈，AI 生成的 Mod 可以按需供给——「描述一个剧本 → 即时生成 → 即刻可玩」。

## 2. 演进策略

基于开源生态（Web 起步、Godot 已排期 M2.5、微信端 CS 架构），按以下路径演进：

**图文冒险引擎平台（初版）→ 精密庞大的 RPG 引擎平台；单人 → 多人。**

核心架构信条：

> 图文冒险 = RPG 去掉战斗/地图/成长系统后的**子集**。
> 内核（实体/属性/事件/状态/条件）第一天就按 RPG 规格设计，图文冒险只是「不配置战斗和地图」的一种内容类型。内核对了，往上加系统是增量；内核错了，就是重写。

## 4.1 M-Agent 设计要点（2026-10-29 晚立项，用户创意）

**定位**：内核除游戏外作为 **Agent harness**——把任务与状态流转配置为 Mod，Agent 在 Mod 构造的工作流中「游玩」；现场性（当前处境+可选动作+后果预览）比 AGENTS.md 开局宣读更具可用性。

**五需求与内核映射**：
1. **Agent 交互接口**：CLI 为基础；约束三层——①动作面收敛（dispatch 事件 + pendingChoice 即动作白名单，协议约束非提示词约束）②工具调用代理（`ygg.tool` 白名单，二期）③现场感注入（叙事化状态回执）
2. **Mod 热修改**：host 侧 watch + 安全点重载（内核 save/load 保状态）
3. **每步自动存档**：每事件后自动 save（host 薄策略）
4. **类肉鸽进化**：一局=一个任务全流程；局末存档+报告 → 经验压缩 → revise 修订 Mod（A4 diff 白名单直接复用）
5. **冷启动 seed mod**：通用元工作流 Mod（intake→decompose→implement→verify→review→done），新 Agent 零定制接入
6. **配置与成长产物入库红线**：游戏设置（静态 `data/config.json` 与动态 `settings.*`）及成长/演进 Mod 均可入库，**只存非敏感行为开关、数值与经验文本**；LLM key、token、连接串、subagent 模型参数等敏感信息只存本地 `.env` / `.env.local`（gitignore），入库资源与报告只允许出现键名（2026-10-29 用户补充）

**架构前提**：不动 ygg-core——全部能力在 host/CLI/内容层生长（D17 actor 语义天然契合 Agent 隔离）。

## 5. 平台化的远期形态

- **内容创作**：AI 生成 + 人工微调（Mod 为 Lua 模板 + 资源数据，均人类可手写；D11/D15）
- **分发**：Mod 导入导出 / 分享链接 → 远期社区化（浏览、评分、改编）
- **审核与安全**：脚本沙箱安全面由沙箱硬约束集承载（D13：无 IO/时钟、燃料/内存上限、API 白名单、确定性执行）；内容审核收敛为资源数据校验 + 脚本静态检查，随平台化引入
- **版本兼容**：Mod Schema 带版本号，内核按版本做迁移策略
